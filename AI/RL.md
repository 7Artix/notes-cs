# RL

RL (Reinforcement Learning)

训练过程为: 做尝试 → 评分 → 计算损失 → 缩小损失 → 梯度下降.

与传统有监督学习的区别是, RL没有正确答案, 只有评分机制, 仅分好坏, 当尝试好时奖励分, 当尝试坏时惩罚分.

各类LLM的训练使用的是 RLHF (Reinforcement Learning from Human Feedback, 基于人类反馈的强化学习). 当模型输出的答案好时, 给予高分, 当回答差时给予低分. 久而久之, 将LLM训练成有礼貌, 能听懂指令的助手.

RL的打分机制与数据是动态的, 不光是对最终结果打分, 而是在任何一个周期内, 根据实时状态进行打分.

# Actor & Critic

RL仍然使用梯度下降学习, RL的核心架构由两个网络组成: Actor & Critic.

Actor: 
- 输入为传感器数据
- 输出为执行器指令

Critic: 
- 输入为系统当前状态(传感器数据, 关节角等)
- 输出为状态价值 (State-Value): 预测根据当前状态, 最终本次行为能得到的总分.

每个时钟周期都会进行评分.

打分机制是人为设计的, 称为**奖励函数设计 (Reward Engineering)**.

以无人机稳定悬停10m这个任务目标为例.

设计奖惩规则:
- **规则A (达成目标):** 如果无人机高度在 9.9 米到 10.1 米之间, 每隔一个周期, 给予 **+1 分** 的奖励.
- **规则B (活着就好):** 如果在空中没有坠毁, 给 **0 分**.
- **规则C (致命惩罚):** 如果无人机高度降到 0 (坠毁), 给予 **-1000 分** 的巨大惩罚, 并强制结束这一次训练 (Restart).

假设飞控芯片为 100Hz, 每 0.01s 进行一次"感知 → 思考 → 行动 → 打分"过程.

该场景下能够实时对状态进行真实打分, 为什么还需要Critic?

Critic是预言家, 预测长期分数, 使Actor能够向长期高分的趋势进化, 而不是局限在当下. 
例如无人机以坠机姿态处于10m的位置, 若按真实评分, 此时应该+1, 但由于其姿态严重有问题, Critic可能打分-1000, Actor参考Critic的意见, 会对坠机姿态进行调整.

针对不同的任务, 有**密集奖励 (Dense Reward)"** 与 **"稀疏奖励 (Sparse Reward)"** 的区别.
