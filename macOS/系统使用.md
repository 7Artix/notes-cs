# 软件的磁盘占用结构

## 沙盒化和非沙盒化App
从App Store下载的App是沙盒化 (Sandboxed) App, 必须遵守**沙盒协议**, 数据仅能存储在:

```shell
~/Library/Containers
```

沙盒化App没有权限操作磁盘中的其他目录.

从其他渠道下载的各个App是非沙盒App, 拥有自由的磁盘操作权限, 按照管理应当将数据存储在:

```shell
~/Library/Application Support
```

但也经常在 `~/Library` 目录下随意创建各种目录存储数据.

## 程序本体与数据

程序本体 (bundle) 保存在 

```shell
/Applications
```

```shell
~/Applications
```


软件数据 (资源库) 存储在:

系统级软件数据, 典型内容包括驱动程序辅助文件, 为全机软件提供服务的组件等.

```shell
/Library/Application Support
```

用户级的软件数据, 当前用户可读写, 当前用户的软件数据. 典型内容包括各类软件缓存, 游戏存档, 浏览器插件, 本地数据库, 聊天记录等.

```shell
~/Library/Application Support
```

## 一些目录

```shell
~/Library/Containers
```

沙盒化App的数据存储目录, 卸载App Store软件后, 也会残留数据.


```shell
~/Library/Caches
```

存储临时文件与缩略图, 可以安全删除, 通常不影响功能, 影响下次打开速度.


```shell
~/Library/Preference
```

存放软件的设置文件 `.plist`. 通常极小, 删除文件可恢复软件设置.


```shell
~/Library/Group Containers
```

存放同一个开发商的多个App之间的共享数据, 经常很大.


```shell
~/Library/Logs
```

运行日志, 删除通常无影响.


```shell
/Users/Shared
```

共享用户目录, 某些开发商喜欢将文件资源放到该目录, 因为所有用户可读.


```shell
~/Library/Application Support/MobileSync
```

备份数据目录.


```shell
~/Library/Developer
```

Xcode相关数据.


## `du` 和 `Finder` 的详细信息

`Finder` 的详细信息中的大小并不是实际磁盘占用, 而是**超额订用 (Over-provisioning)**, 是一个**稀疏文件 (Sparse Files)**, 充当虚拟机的硬盘, 是一个**逻辑大小**, 告知系统最大容量, 以及预留的编号量, Finder读取后, 显示的是该大小.

`du` 读取的是磁盘占用, 查看磁盘上的扇区占用数量, 是真实的大小 (**物理大小**).

`ls -lh` 显示的也是逻辑大小.


## docker专清

删除所有停止的容器, 未使用网络和悬空镜像:

```shell
docker system prune
```

连带未使用镜像一起删除:

```shell
docker system prune -a
```

清理数据卷:

```shell
# 查看所有卷
docker volume ls
# 删除所有未被挂载的卷
docker volume prune
```

**Docker不会自动归还物理磁盘空间**. Docker只增不减, 即使删除了数据, 也只是在Docker内部标记了数据空间重新可用. 但APFS有稀疏文件空洞回收, 能够回收空间.

Docker.raw是一个中间层的Linux虚拟机的整个硬盘. 它包含了:
- Linux操作系统的自身文件.
- 下载的所有镜像.
- 容器的可写层.
- 本地数据卷.

使用如下命令查看镜像, 容器, 卷的总大小:

```shell
docker system df
```

查看所有container的大小:

```shell
docker ps -as
```

查看所有镜像大小:

```shell
docker images
```

删除构建过程的cache:

```shell
docker builder prune
```
